# Plan: sdlc-run 4.0.0

Design (binding): `docs/designs/2026-11-23-sdlc-greenfield.md` on `docs/sdlc-greenfield-design` (PR 61), section "Build order for 4.0.0". Owner decisions on top: records in `~/.sdlc/runs/<run-id>/` (never committed), branch `sdlc/<run-id>` in every repo, `~/.sdlc/active/` links, one owner approval, no per-job sandbox, up to 8 builders, milestones merge locally into the project branch, only PR is project into main, models only in the kickoff, no installs in product repos, `sdlc clean` instead of adopt.

## Decisions taken (technical, recorded here)

- **Runner:** plain Python stdlib in `plugins/cct/skills/sdlc-run/runner/`; one CLI `sdlc.py`; `SDLC_HOME` overrides `~/.sdlc` for tests.
- **Receipts:** HMAC-signed with a per-run key written by the runner; `sdlc check` verifies. Stops accidental forgery; a hostile same-user process is out of scope (design's accepted risk).
- **Ref names:** `sdlc/<run-id>` is the project branch; milestone and task branches are `sdlc-m/<run-id>/<m>` and `sdlc-t/<run-id>/<t>` (git cannot hold `sdlc/x` and `sdlc/x/y`).
- **3.x kit stays in the plugin as legacy data:** `sdlc clean` needs the shipped hashes (`scripts/kit-hashes.json`), and this repo's own 3.x copies and tests stay green. SKILL.md routes nothing to `adopt`.
- **Reuse:** FAIL vs BLOCKED, pass bound to commit, full suite before push, design-input guide, `e2e-repeat.sh` (taken from PR 60, unmerged).
- **Hook:** one narrow PreToolUse guard for `~/.sdlc/runs/` (the owner decision and design 3.2 require it).
- **3.x doc-pin tests** (six tests that asserted 3.x SKILL.md wording) and the 3.x stage test of the docs page were removed; the 3.x kit tests otherwise stay.
