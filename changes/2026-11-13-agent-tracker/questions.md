# Questions: agent-tracker

One entry per open question: the question, the default taken, and where it lands. Written during the build; the owner reads it at the close.

## Feature 1

- **Q1 (F4, step 3): which `waitingFor` value means a permission prompt?** A session was waiting when step 3 ran, with `waitingFor: "input needed"`. Its last transcript entry was an `AskUserQuestion` tool call, so that value is what a question wait reports, not a permission prompt. **Default taken:** no permission value was recorded, so `PERMISSION_WAITING_FOR` is `null`, "asks permission" never shows, and any `waitingFor` gives "waiting" (F4's own fallback). The scrubbed row is the fixture `tests/fixtures/agents.ts`. **To change:** record `waitingFor` from a session that waits on a permission prompt and set the constant in `core/types.ts`.
- **Q2 (F128, step 4): does the mod API have a rename?** No: `$.fs` has `read`, `write`, `list`, `exists`, `stat` and `ancestors`, and no rename or append. **Default taken:** F128's own fallback. `agents.json` and `poller.json` are written whole and a reader keeps its last good copy. The test title keeps the fact's words; its body asserts the whole-file write. **To change:** use a rename when the API gains one.
- **Q3 (F21): what counts as tokens in?** The fact says "tokens in and out". **Default taken:** in is `input_tokens` plus cache reads plus cache writes (everything the model read), out is `output_tokens`, summed over every turn of the session, subagents included. **To change:** edit `addTokens` in `core/usage.ts`.
- **Q4 (F11): which background sessions belong to a session?** The list has no parent link. **Default taken:** background sessions that are not done and run in the same folder as the session. **To change:** match on a parent id if the engine adds one.
- **Q5 (types): two fields were added to the plan's record.** `SessionRecord.source` also takes `'engine'` (a session only the list shows, no file) and the record has `unknownValue` (the raw engine value behind "state unknown", F66). Both are in `hooks/tracker/types.d.ts`. **Default taken:** add them, since F20, F66 and F131 need them. **To change:** none needed.
- **Q6 (F17): where does the question check read the last message?** `turn.complete` carries `answer` and `$.session.messages()` carries the rows. **Default taken:** the last assistant row of `$.session.messages()` (the session's transcript), else `answer`. Aborted turns and subagent turns get no check.
- **Q7 (build): `$` can only be passed to top-level `function` declarations.** The engine's source scan refused a helper that took `$` as an arrow or a method. **Default taken:** every I/O helper is a top-level `function`, and the snapshot atom is declared in `collector.ts`, where it is updated. Rows 3 and 4 declare the same literal `{ plugin: 'agent-tracker', key: 'snapshot' }` where they read it.
- **Q8 (mod load): a mod loaded mid-session has no `session.start`.** **Default taken:** the record starts at the first owner prompt or the first 5-second poll after a `/clear`; a mod switched on mid-session needs a restart (the README says so).

## Feature 2

- **Q9 (F12, F13, F70): how does the backfill read a transcript?** One pattern pulls a few fragments (timestamps, folder, branch, title, message ids with usage, error flags, prompt strings) out of the text. In memory it is a JS regex; over 4 MiB the same pattern runs as `grep -a -o -E`, so both paths give one record. Checked against the real BSD `grep` on the fixture and on two real transcripts (identical fragments). **Default taken:** a prompt is an ask unless it is a sidechain line, a meta line, `promptSource: system`, or starts with a known system tag (`<command-name>`, `<bash-input>`, `<bash-stdout>`, `<task-notification>`, `<system-reminder>`...), `[Request interrupted` or `This session is being continued`. Shell input (`<bash-input>`) is not an ask. Retries are 0 (the call inputs are not read). Output cut at 4 MiB drops its last fragment. A prompt with an image grep-prints the image bytes in its fragment. **To change:** edit `NOT_AN_ASK` or `FRAGMENT` in `core/transcript.ts`.
- **Q10 (F12): how often does the backfill run?** **Default taken:** once at start and once a minute, on its own timer, at most 25 transcripts per pass, only transcripts changed in the last 7 days whose `transcripts/` file is older than the transcript. A session with a `sessions/` file, and the mod's own session, are never read. An unreadable transcript gets a record with no asks and no numbers, and is tried again only when the file changes (F55). **To change:** `BACKFILL_MS` and `BACKFILL_MAX` in `backfill.ts`.
- **Q11 (F69, F125): where does the duration format live?** Row 3 owns `core/format.ts` and F125. **Default taken:** this row creates the file with `duration` only, following F125 ("<1m", "6m", "2h 10m", "3d"), and writes whole hours as "2h" so the F69 line reads "PRs as of 2h ago". Row 3 adds to the file and keeps `duration`. **To change:** none needed.
