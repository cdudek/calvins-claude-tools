# Questions: agent-tracker

One entry per open question: the question, the default taken, and where it lands. Written during the build; the owner reads it at the close.

## Feature 1

- **Q1 (F4, step 3): which `waitingFor` value means a permission prompt?** A session was waiting when step 3 ran, with `waitingFor: "input needed"`. Its last transcript entry was an `AskUserQuestion` tool call, so that value is what a question wait reports, not a permission prompt. **Default taken:** no permission value was recorded, so `PERMISSION_WAITING_FOR` is `null`, "asks permission" never shows, and any `waitingFor` gives "waiting" (F4's own fallback). The scrubbed row is the fixture `tests/fixtures/agents.ts`. **To change:** record `waitingFor` from a session that waits on a permission prompt and set the constant in `core/types.ts`.
- **Q2 (F128, step 4): does the mod API have a rename?** No: `$.fs` has `read`, `write`, `list`, `exists`, `stat` and `ancestors`, and no rename or append. **Default taken:** F128's own fallback. `agents.json` and `poller.json` are written whole and a reader keeps its last good copy. The test title keeps the fact's words; its body asserts the whole-file write. **To change:** use a rename when the API gains one.
- **Q3 (F21): what counts as tokens in?** The fact says "tokens in and out". **Default taken:** in is `input_tokens` plus cache reads plus cache writes (everything the model read), out is `output_tokens`, summed over every turn of the session, subagents included. **To change:** edit `addTokens` in `core/usage.ts`.
- **Q4 (F11): which background sessions belong to a session?** The list has no parent link. **Default taken:** background sessions that are not done and run in the same folder as the session. **To change:** match on a parent id if the engine adds one.
- **Q5 (types): two fields were added to the plan's record.** `SessionRecord.source` also takes `'engine'` (a session only the list shows, no file) and the record has `unknownValue` (the raw engine value behind "state unknown", F66). Both are in `hooks/tracker/types.d.ts`. **Default taken:** add them, since F20, F66 and F131 need them. **To change:** none needed.
- **Q6 (F17): where does the question check read the last message?** `turn.complete` carries `answer` and `$.session.messages()` carries the rows. **Default taken:** the last assistant row of `$.session.messages()` (the session's transcript), else `answer`. Aborted turns and subagent turns get no check.
- **Q7 (build): `$` can only be passed to top-level `function` declarations.** The engine's source scan refused a helper that took `$` as an arrow or a method. **Default taken:** every I/O helper is a top-level `function`, and the snapshot atom is declared in `collector.ts`, where it is updated. Rows 3 and 4 declare the same literal `{ plugin: 'agent-tracker', key: 'snapshot' }` where they read it.
- **Q8 (mod load): a mod loaded mid-session has no `session.start`.** **Default taken:** the record starts at the first owner prompt or the first 5-second poll after a `/clear`; a mod switched on mid-session needs a restart (the README says so).

## Feature 2

- **Q9 (F12, F13, F70): how does the backfill read a transcript?** One pattern pulls a few fragments (timestamps, folder, branch, title, message ids with usage, error flags, prompt strings) out of the text. In memory it is a JS regex; over 4 MiB the same pattern runs as `grep -a -o -E`, so both paths give one record. Checked against the real BSD `grep` on the fixture and on two real transcripts (identical fragments). **Default taken:** a prompt is an ask unless it is a sidechain line, a meta line, `promptSource: system`, or starts with a known system tag (`<command-name>`, `<bash-input>`, `<bash-stdout>`, `<task-notification>`, `<system-reminder>`...), `[Request interrupted` or `This session is being continued`. Shell input (`<bash-input>`) is not an ask. Retries are 0 (the call inputs are not read). Output cut at 4 MiB drops its last fragment. A prompt with an image grep-prints the image bytes in its fragment. **To change:** edit `NOT_AN_ASK` or `FRAGMENT` in `core/transcript.ts`.
- **Q10 (F12): how often does the backfill run?** **Default taken:** once at start and once a minute, on its own timer, at most 25 transcripts per pass, only transcripts changed in the last 7 days whose `transcripts/` file is older than the transcript. A session with a `sessions/` file, and the mod's own session, are never read. An unreadable transcript gets a record with no asks and no numbers, and is tried again only when the file changes (F55). **To change:** `BACKFILL_MS` and `BACKFILL_MAX` in `backfill.ts`.
- **Q11 (F69, F125): where does the duration format live?** Row 3 owns `core/format.ts` and F125. **Default taken:** this row creates the file with `duration` only, following F125 ("<1m", "6m", "2h 10m", "3d"), and writes whole hours as "2h" so the F69 line reads "PRs as of 2h ago". Row 3 adds to the file and keeps `duration`. **To change:** none needed.
- **Q12 (F14, F67): when does the scan run, and where is it kept?** **Default taken:** one scan at the start and one every 2 minutes, on its own timer so the 5-second poll never waits on `gh`. It runs only in the session's own folder and only when the session has a repo. The result is the `scan` block of the session's own file. `gh pr list` asks for the 100 newest open PRs. Checked on the real `gh` and `git` output of this repo. **To change:** `SCAN_MS` in `scan.ts`.
- **Q13 (F54, F69): does the scan time move when gh fails?** **Default taken:** no. When `gh` is missing or signed out, the scan keeps the last PRs and their `at`, sets `ghOk` to false and still reads the worktrees, so the Repo page can say how old the PRs are. With no earlier scan the PRs are empty and `at` is the time of the try. **To change:** `scanPass` in `scan.ts`.
- **Q14 (F69): what is a live session?** **Default taken:** a record with `source` "mod" whose state is not ended. A session the list shows without the mod does not count, so its repo shows the stored PR state with its age. **To change:** `repoPrs` in `core/git.ts`.

## Feature 3

- **Q15 (F25, F26): who is named when this session waits?** F25 names the oldest waiting session and F26 says "while this session is the oldest waiting", but its scenario has this session at 1m and the other at 6m and reads "this session 1m · web-app 6m". **Default taken:** the scenario wins. Whenever this session waits, the band names it first ("this session 1m"), then the oldest other one. With no other waiting it reads "● 1 needs you · this session 1m". **To change:** `needsSegment` in `core/band-model.ts`.
- **Q16 (F28): what drops after the spec's five steps?** At 50 columns the five steps leave 54 cells. **Default taken:** step 6 drops the running and done counts, step 7 the waiting session itself, then only "● 2 need you" and the buttons stay. Below 40 columns it goes to step 7 at once. **To change:** `LAST_STEP` and `build` in `core/band-model.ts`.
- **Q17 (F80, F84): the details buttons are 24 cells, not 21.** A plain Button with a hotkey draws "c: Copy", "p: Pane", "d: Compact": 7 + 7 + 10. The compact pair (17) matches the spec. **Default taken:** count 24, so the header fits `bodyColumns` less 24 and the cut thresholds sit 3 cells earlier than the spec's 21 would give. **To change:** `BUTTONS_DETAILS` in `core/band-model.ts`.
- **Q18 (F54, F87): where does the "PRs not shown" line show?** The plan says the band stays quiet and the pane shows the line; F87 says the details view shows its Partial line. **Default taken:** the compact band only drops the PR segment; the details view drops the PR column and writes "PRs not shown: gh is not installed or not signed in. Run gh auth login to see them." under the header. A repo never scanned also shows no PR segment and no line. **To change:** `prsOf` and `detailsLayout` in `core/band-model.ts`.
- **Q19 (spec, spacing): the buttons have no gap in the count.** The spec's 125 cells hold no gap between the two buttons or before them, and its Components table says "Box (row, gap 2)". **Default taken:** measured as the spec counts, with no `gap` on the row, so spare room sits before the buttons and the thresholds match the spec (114, 99, 79, 65, 54). If a real terminal shows the buttons touching ("p: Paned: Details") when the row fits exactly, add `gap={1}` to the button pair and add 1 to `BUTTONS_COMPACT` and `BUTTONS_DETAILS`; every threshold then moves one cell. **To change:** `band.tsx` and `buttonCells` in `core/band-model.ts`.
- **Q20 (hooks): where `/tracker` lives until row 4.** The collector holds the one unmatched `session.start`, and `register(on)` has no `$`. **Default taken:** `band.tsx` registers the command at the first `AbovePrompt` draw and holds a `command.run` hook matched on `tracker`. It answers `details`, `compact`, `copy`, `band on` and `band off`, and calls `next(e)` for every other word and for bare `/tracker`. A second matched `command.run` hook for `tracker` loads and chains (checked with `validate --strict` and `claude plugin test`), so row 4 adds its own hook for the pane's words. Bare `/tracker` does nothing yet. **To change:** none needed; row 4 handles it.
- **Q21 (types): the snapshot gained two fields.** `Snapshot` has `okAt` (time of the last good list read, 0 for none) and `failedReads` (failed reads in a row) for F52 and F123; `at` 0 means the first read is pending (F53). The collector sets them. Row 4 reads the same fields. **To change:** none needed.
- **Q22 (F23): what does Pane open before row 4 draws it?** **Default taken:** `$.ui.open({ id: 'tracker', title: 'Tracker' })`, with `PANE_ID` in `core/types.ts`. Row 4 draws that pane with `ui.render` on `Pane` and `requestId: 'tracker'`. **To change:** `PANE_ID`.
- **Q23 (F85): the Markdown layout.** The facts fix the content, not the layout. **Default taken:** a "Tracker state" heading, the four counts as bold-labelled bullets, then "Needs you", "Running" and "Open PRs" lists ("web-app: fix login, waiting 6m"; "web-app #12 Fix login (checks failing, approved, mergeable)"). No folder path appears; a repo that shares its name with another carries its parent folder as in F7. **To change:** `core/markdown.ts`.
- **Q24 (F33, F34, F84): header fallbacks and what runs.** **Default taken:** no title shows "untitled session"; a null branch in a repo shows "detached HEAD"; a session in no repo shows its folder name where the repo goes. What runs joins the header line when the whole fits, else takes a second line; once the header is cut it always has its own line. The cut ladder is branch, session title, then "2/4 complete", then the milestone name. **To change:** `headerAt` and `headerLines` in `core/band-model.ts`.
- **Q25 (F81, F82): column lines.** **Default taken:** the needs-you column names this session when it is the oldest ("this session 10m"); the PR column drops a part at 0 ("2 mergeable" alone) and shows no line when both are 0; the PR count reads "1 PR" for one and "n PRs" otherwise. **To change:** `detailsLayout` and `build` in `core/band-model.ts`.

## Feature 4

- **Q26 (F92): does Escape hand back first and close second?** `$.ui.open` with `closeOnEscape` makes the first Escape both return the keys and close the pane, and a later Escape at an idle empty prompt close it; the fact wants the first Escape to hand the keys back and only the second to close. Refusing the first close in a `ui.close` hook would also refuse the Close mark (same origin `person`). **Default taken:** open with `focus` and `closeOnEscape` as asked, so Escape closes; the fact's two-step reading is not built. **To change:** drop `closeOnEscape` in `openPane` in `store.ts` (Escape then only returns the keys) and decide how a second Escape closes.
- **Q27 (F43, F89): how does the pane know the ring and "reopened"?** The mod gets `ui.focus` only before the ring moves, and no event for a reopen. **Default taken:** Back returns to the row whose press opened the page (an Enter or a click is a press on the focused row), drawn `autoFocus`; Home starts on its first session row. The frozen order is kept while `isFocused` is true and dropped when a draw has `isFocused` false or when `/tracker` or the Pane button opens the pane. Closing with `ctrl+x x` and reopening by a path that is neither is not seen. **To change:** `openPane` and the `ui.render` hook in `pane.tsx`.
- **Q28 (spec, Home): where does the Partial line go?** `screens.md` Sections puts the stale or partial line directly under the title; `interaction.md` Partial says "one dim line at the bottom". **Default taken:** `screens.md` (the layout source): under the title, above the without-the-tracker line. **To change:** `homeView` in `pane/home.tsx`.
- **Q29 (F45, F102): where is this session when it is alone?** Empty says "one line, then Ended today and the Repos line". **Default taken:** alone and not waiting, Needs you shows the Empty line and Running and Done are hidden (this session is their only row); alone and waiting, this session is the one row under Needs you (named "this session") and no Empty line shows. The Session page of an alone session opens by `/tracker session <text>`. **To change:** `alone` in `homeModel` (`core/pane-model.ts`).
- **Q30 (F40, F124): what does a Needs you row call this session, and what is the word beside a glyph?** F102 says "this session". **Default taken:** its title is replaced by "this session" on Needs you only (Running and Done keep the title). Every row's glyph sits under a section heading that names the state and beside a time count; the Session state line names it too. **To change:** `rowOf` in `core/pane-model.ts`.
- **Q31 (F99, F110, zoom): zoom 150 percent is not known to the mod.** No prop says the zoom. **Default taken:** the width rules only (70 columns). **To change:** read the zoom if the pane props gain it.
- **Q32 (F51, F119): what does the Repo page say for a repo never scanned?** No scan block is neither "no open PRs" nor "gh missing". **Default taken:** "No open PRs." (the scan runs at start, so this is brief, and a repo with no PR segment is a repo with none to show). **To change:** `repoModel` in `core/pane-model.ts`.
- **Q33 (F122, spec): `/tracker session` or `/tracker repo` with no text, and ask times.** The fact defines no empty argument; the spec's ask row has a time column but no sample. **Default taken:** an empty argument opens Home; an ask's time is how long ago it was asked ("30m", no "ago", to fit 6 cells). Repo names match by substring only, like titles. **To change:** the `command.run` hook in `pane.tsx`; `sessionModel` in `core/pane-model.ts`.
