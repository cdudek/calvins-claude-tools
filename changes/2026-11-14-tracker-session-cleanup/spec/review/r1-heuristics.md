## Contradictions between files

1. **Ended versus `done` with a process.** `ia.md` Objects defines an ended session as "absent from Claude Code's list, listed with no `pid` ..., or reported `done`", but the `ia.md` state diagram has `done --> ended: the process exits`, and `conformance.md` calls "interactive done" a live state. (R1-06)
2. **Focus after Clear.** `ia.md` Move table: "focus on the first action". `interaction.md` Clearing: "the ring rests on the crumbs". `screens.md` and `interaction.md` Offer: "focus on Keep worktree". (R1-17)
3. **Confirm on Clear.** `intent.md` Constraints: "a confirm before anything that cannot be undone". `brief.md` Open Questions and `interaction.md` Action Behaviour: no confirm, although the same table says closed tasks and the list row cannot be restored. Recorded as C2; still open. (R1-01)
4. **Where ended sessions are listed.** `interaction.md` J1 wireflow cites an "Ended" section on Home; `screens.md` Home Sections lists no such section. (R1-10)
5. **Worktree line weight.** `screens.md` Sections row 6 says "One dim line" for the "why it stays" case; `screens.md` Words marks the same "Worktree stays" lines "normal weight". (R1-21)
6. **Meaning of "Skipped".** `interaction.md` J6 wireflow uses "the report's 'Skipped' line" for running sessions; the tidy state "Skipped" is the owner's "Skip these N" answer. (R1-13)
7. **The one confirm.** `intent.md` and `brief.md` J4 say worktree removal is after one confirm; `ia.md` says `claude rm` removes a session's own worktree "if safe", so a confirm-free Clear can remove one. (R1-02)
8. **What J2 asks.** `intent.md` J2: "see when it last did anything, not when the tracker first saw it". `brief.md` J2 adds "when it started". The added word ("started") has no named source. (R1-07)
9. **Separator and wording of the first line.** "·" in `brief.md`, `ia.md` and `sitemap.md`; two spaces in `screens.md` and `interaction.md`. (R1-22)
10. **Clear is "primary" but second.** `ia.md` CTA inventory calls Clear primary and Copy resume command secondary; `screens.md` puts Copy resume command first in the row and in the ring. Deliberate and recorded (double Enter), so the CTA inventory should say "primary, second in the row".
11. **Stale wording of the "Keep worktree" undo.** `ia.md` CTA inventory and `interaction.md` Action Behaviour: "the offer returns the next time Clear is pressed". `interaction.md` State "Nothing to clear" shows no Clear button, so this holds only while a passing worktree keeps the state at "something to clear" (R1-08).
12. **Spelling of one command argument.** `sitemap.md` command words: `repo <text>`; `screens.md` Command hint: `repo <name>`. Low.

## Heuristics with no finding

H1 for Clear and Remove (dim "Clearing…" and "Removing worktree…" lines, results that stay on the page), H3 for the Back target and the unchanged Close, H4 for glyph and colour use (`✓` and `✗` beside words, colours from the theme), H5 for the ring that starts on Copy resume command and never on a destructive button, H7 for `/tracker session <text>` as the keyboard route, H9 for the main error strings (event, consequence, action), and the brief's no-gos N1 to N9 all hold up. The Home and band changes follow the owner's rules (spaced buttons, no hotkeys, tasks first, calm dashboard).
