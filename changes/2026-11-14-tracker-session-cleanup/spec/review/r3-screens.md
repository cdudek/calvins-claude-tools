## Safety of Clear and the worktree offer

- Double press: a double click is safe (the button is gone); a double Enter leaves the page (R3-07). A late second Enter after the offer lands on Keep worktree: safe, the spec's best decision.
- A changed Claude Code list format can make live sessions look ended and expose Clear on them (R3-24).
- Stale checks: Remove worktree re-checks the five conditions, and `git worktree remove` without force refuses a dirty tree, so a stale "clean" cannot lose uncommitted work. Condition 5 (no live session) and Clear's own process test both read the snapshot; only the first is re-checked at press (R3-03).
- Wrong thing removed: a fresh worktree passes all five conditions (R3-06). The branch is kept, so no commit is lost, but the resume path is (R3-01).
