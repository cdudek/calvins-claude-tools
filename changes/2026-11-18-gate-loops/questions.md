# Questions

Asked during the build; the build never stops on them. Each has the default taken.

- **Q1 (2026-11-18) When to lock the tests?** The plan says lock after feature 1's failing tests, but features 2-4 also add tests, and the lock refuses every test file edit on the milestone branch. **Default taken:** one test-first commit with the failing tests for all facts (F1-F15, N1) and the fixture updates, then `testLocked: true`, then features 1-4 build code only. If a locked test proves wrong, the build records it here and asks for `testEdit`.
- **Q2 (2026-11-18) Security review flagged the test lock as self-grantable.** An automated review of the `testLocked` commit found three weaknesses that already existed in `chain-gate.sh`: (1) `decisions.json` is exempt from the gate, so an agent could write `testEdit`/`protectedEdit` itself; (2) `.claude/` and `*.md` paths exit before the test-lock and protected-path checks; (3) `codex-build.sh` and `chain-gate.sh` use different test globs. **Default taken:** out of scope here (not in `## Files that change`, and no fact covers it). This build never writes `testEdit` or `protectedEdit`. Proposed follow-up change: consent keys written only by `verify_gate.py` next to `lock.json`, `.claude/hooks/**` protected after approval, and one shared `testGlobs`.
