# PRD examples

### Example 1: a PRD that is read (guided onboarding)

The worked example runs through `references/phases.md`, one visit at a time: page one, then
solution and requirements, then launch, then impact.

**Why it works:**

- Page one has no solution; the problem carries a quote, a number and a support theme, each with a source
- The segment is "solo founders, no IT, 500k", not "users"
- One metric with a baseline and target, one guardrail, both with a date to check
- Non-goals name the three adjacent requests someone would assume
- Requirements are numbered EARS sentences; every adjective became a number
- The Decisions table carries the rejected options, so "mandatory tour?" is never reopened
- Impact is filled in, and the verdict is honest: moved, short of target

### Example 2: a PRD nobody reads (feature list)

**Problem:** "Users want better onboarding."
**Solution:** "Add onboarding."
**Requirements:** "1. Onboarding flow 2. Tooltips 3. Help docs"

**Why it fails:**

- No evidence (who said so, how many, when?)
- No segment ("users")
- No metric (what is "better"?)
- No non-goals (is personalisation in? video?)
- Requirements with no number, so nothing can be tested or declined
- No owner, no decisions, no impact

**The fix is the workflow, not a longer document:** page one with evidence, a segment and one
metric (visit 1); numbered requirements and the first Decisions rows (visit 2); launch readiness
with names (visit 3); the Impact table on the date the metric names (visit 4).
